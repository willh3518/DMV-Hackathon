## Product shorthand

This project is a conversational accessibility-matching application for restaurants and other places. It combines a user's profile and current request with business-declared information and review-derived observations.

Remember these invariants:

1. Match results are personal, not universal.
2. Accessibility attributes remain separate.
3. No evidence is unknown, not inaccessible.
4. Declared claims and observed experiences remain distinguishable.
5. Every result should explain evidence, confidence, strengths, concerns, and uncertainty.

## Working style

- Make focused, reviewable changes suitable for a short hackathon.
- State assumptions when product behavior is not specified.
- Prefer simple foundations that can be demonstrated reliably over speculative infrastructure.
- Keep future setup instructions and architectural decisions documented.
